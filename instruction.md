A failed reference-data migration stalled a regulatory submission run. The transaction ledger it files from was truncated part-way through, and the reporting engine that reads it still decides what to file under draft rules the compliance committee has since reversed. Rebuild that ledger and restore the engine, so that a run of it produces a submission the committee would recognise as its own.

The truncated ledger sits at `/app/data/transaction_ledger.json` and the engine at `/app/workflow/build_report.go`. What the engine files is only as good as that ledger, and the rebuilt one is what it reads at that path. A pre-migration snapshot and a journal of the changes the migration posted after it survive beside the truncated file under `/app/data`. How the two combine, which booking a change names, what a withdrawal does, what a later reinstatement brings back and the order of the result are governance decisions, and the ledger is restored at its expected path. Whatever you rebuild it with is yours to keep or throw away; of that step, only the file at that path is graded.

The restored engine is a Go program built with the toolchain installed here. It stays one `package main` in that one file at `/app/workflow/build_report.go` and is compiled from that file alone, so a helper split into a sibling source beside it never reaches the build. That one source is the whole engine: the compiled program does the reporting itself and never hands the run off to another program or interpreter.

Preserve its `--input` and `--output-dir` options and their defaults; the counterparty register, the regulatory calendar, the rate table and the reporting policy are always read from their fixed absolute paths under `/app/data`, and `--input` selects the ledger only.

`/app/docs/reporting_contract.json` is the output contract: paths, schemas, required-field lists, container shapes and sort orders. Those two are the whole of its interface: it declares no other option, so there is no second way to name an input to it. It says nothing about how any value is derived. Reconstruct that from `/app/incident/compliance_governance_log.md`, mostly routine committee minutes, where the later dated decision governs; the minutes are a document you read while you work rather than an input a run opens, and an engine that has the decisions right owes them nothing at run time.

A run writes exactly `/app/output/summary.json`, `/app/output/report_lines.json` and `/app/output/exception_queue.jsonl` where the flag is left at its default, and those same three names in the directory `--output-dir` names where it is given.

That directory is one the run may empty and fill, which `/app/data` -- where the documents it reads live -- is not: a run handed `/app/data` names it on standard error and exits non-zero, having written and cleared nothing, since clearing the directory its own inputs sit in is not an end state this contract admits.

A conforming run finishes inside the contract's 90-second budget and leaves the output directory holding those three and nothing else, so a run writes into the directory it finds and clears whatever an earlier run left there rather than passing it off as its own output.

The contents go; the directory itself stays, since the run does not own the path it writes into, and when an engine run finishes nothing outside its output directory has been added to, changed or taken away by that run -- a scratch file elsewhere is the run's own business while it lasts, and it goes when the run does.

These hold of the artifacts and of the program that produces them, and a run that misses any of them is not a correct one. Every value in them is derived from the operational inputs: correct on any ledger that conforms to the contract rather than on the graded one alone, identical across reruns. The recovery sources and the rule documents are what this work is done from rather than things it writes, so the pre-migration snapshot, the ledger journal, the counterparty register, the reporting calendar, the rate table, the reporting policy and the governance log all come back byte for byte unchanged, and the frozen snapshot `/app/workflow/.build_report.original.go` is left exactly as it is.
