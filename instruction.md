A failed reference-data migration stalled a regulatory submission run. It truncated the authoritative transaction ledger at `/app/data/transaction_ledger.json` and left the reporting engine at `/app/workflow/build_report.go` deciding what to file under draft rules the compliance committee later reversed. Nothing the engine files can be trusted until that ledger is rebuilt. A pre-migration snapshot and a journal of the changes the migration posted after it survive beside the truncated file under `/app/data`. How the two combine, which booking a change names, what a withdrawal does, what a later reinstatement brings back and the order of the result are governance decisions, and the ledger must be restored at its expected path first.

Then restore the engine, a Go program built with the toolchain installed here. It stays one `package main` in that one file at `/app/workflow/build_report.go` and is compiled from that file alone, so a helper split into a sibling source beside it never reaches the build. That one source is the whole engine: the compiled program does the reporting itself and never hands the run off to another program or interpreter. Preserve its `--input` and `--output-dir` options and their defaults; the counterparty register, the regulatory calendar, the rate table and the reporting policy are always read from their fixed absolute paths under `/app/data`, and `--input` selects the ledger only. `/app/docs/reporting_contract.json` is the output contract: paths, schemas, required-field lists, container shapes and sort orders. It says nothing about how any value is derived. Reconstruct that from `/app/incident/compliance_governance_log.md`, mostly routine committee minutes, where the later dated decision governs. A run writes exactly `/app/output/summary.json`, `/app/output/report_lines.json` and `/app/output/exception_queue.jsonl` inside the contract's 90-second budget, and leaves that directory holding those three and nothing else, so a run writes into the directory it finds and clears whatever an earlier run left there rather than passing it off as its own output. The contents go; the directory itself stays, since the run does not own the path it writes into, and when the run finishes nothing outside that directory has been added to, changed or taken away by it -- a scratch file elsewhere is the run's own business while it lasts, and it goes when the run does. Derive every value from the operational inputs: correct on any ledger that conforms to the contract rather than on the graded one alone, identical across reruns. The recovery sources and the rule documents are read rather than rewritten, so the pre-migration snapshot, the ledger journal, the counterparty register, the reporting calendar, the rate table, the reporting policy and the governance log all come back byte for byte unchanged, and the frozen snapshot `/app/workflow/.build_report.original.go` is left exactly as it is.
